# 单元格渲染先后顺序说明

## 一、概述

报表渲染时，单元格必须按照父子格依赖关系从父到子依次处理。只有当一个单元格的左父格和上父格都已处理完毕，该单元格才会被渲染。这一机制确保了数据展开和父子联动时的正确性。

---

## 二、渲染流程

后端渲染流程如下：

1. **构建父子格关系**：遍历所有单元格，根据 `leftParentCellName`/`topParentCellName` 建立父子引用链，确定根单元格（无左父格且无上父格的单元格）
2. **从根单元格开始**：将根单元格加入待处理队列
3. **按依赖顺序处理**：从待处理队列中取出单元格，只有其左父格和上父格均已处理完毕时才执行渲染；若父格未处理完则跳过，等待下一轮
4. **子格入队**：单元格渲染完成后，其子格被加入待处理队列，继续按依赖顺序处理
5. **循环直至完成**：重复步骤 3~4，直到所有单元格处理完毕

---

## 三、关键规则

- **先父后子**：父格必须先于子格处理，子格依赖父格的展开结果
- **SimpleValue 优先**：值为 `SimpleValue`（`type: "simple"`）的单元格不依赖父格处理状态，可优先处理
- **循环依赖报错**：若存在循环依赖（如 A 依赖 B，B 又依赖 A），则抛出 `CellDependencyException`
